# v03.2: Hear about a surge on a saved station with the app closed

Plan: [feature-surge-alerts](feature-surge-alerts.md)
Groundwork: [04-surge-alerts](../research/groundwork/04-surge-alerts/)
Intake: [03-tide-feedback](../research/intake/03-tide-feedback/)
Pull request: #212
Sessions: worker-c (8f1e2a40-77c3-4b9d-a0e2-5c61d9b3f104)

Most beta testers keep the app closed, so an advisory shown only in an open tab reaches almost nobody. The groundwork track settled push over email, and this task builds it.

## Outcomes

- [x] Saving a first station asks for notification permission, and declining it still saves the station
- [x] A surge advisory on a saved station arrives as a notification with the app closed
- [x] An advisory lifted before delivery never shows
- [ ] Operator check: a push reaches a real phone on the Cascais station during a live advisory

## Findings

- **planner, 2026-03-11:** intake item 3 in `01-alerts.md` is the origin, and items 1 and 2 ship apart as the banner bundle
- **worker-c, 2026-03-14:** the plan suggested asking for permission on the station page, and the review moved it to the save action, since the page asked before anyone had saved anything

> Test strategy: unit for the send queue's expiry, component for the permission prompt, manual for delivery on a real phone
