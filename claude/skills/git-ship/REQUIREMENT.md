# Git ship requirement

## Gap

Without this skill, the post-feature sequence runs from memory. Doc sync gets skipped, or runs after staging has closed so its output never reaches a commit. A session chaining by hand narrates between steps, which turns one flow into a conversation and invites a decision at every boundary.

The sequence also reaches the remote on work nothing re-checked. This skill is where an `auto-ship` stop resumes, so a fix the user makes by hand after a failed verify is pushed with no suite run against it. A chain that ends on its CI watch line, or never reads the evidence thread, reports done on a pull request still owed a result.

## Must

- The project's verify commands run before the sequence and a failure stops it, and a project naming none is said so rather than read as passing
- Each step runs through the Skill tool in the stated order, with staging after the sync skills write, and the chain reaches the pull request on a branch already committed
- No text appears between steps beyond a stop report and the background watch line, and the body names the one point a wrapping caller may act at and when the closing block is not emitted
- CI is watched to a terminal state in the background, and a failure stops the chain naming the check
- Done is reported only once `canon pr evidence <number> --check --json` reads `settled`, re-read once after running what it owed, and a binary lacking `--check` reads as unread

## Must not

- Auto-trigger
- Fix a failing check or attempt a fix for a failing verify
- Implement or review
- Report the chain done before the CI watch exits

## Out of scope

- Implementation and review, which `auto-ship` chains ahead of this same sequence
- The behavior of each step, which the skill it invokes owns
