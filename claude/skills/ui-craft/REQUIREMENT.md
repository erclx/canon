# UI craft requirement

## Gap

Without this skill, the UI behavior practice reaches a session only as path rules a target has to sync, so a project holding the plugin without governance builds a component with none of it. A role that plans, builds, or reviews a rendered change has no name to load the practice by, and each one restates the part it remembers.

## Must

- Every rule the retired ui practice rules carried sits in a reference, unchanged in wording, with its source row in a ledger beside the reference
- A rendered change reaches accessibility, keyboard, and state coverage on every read, and the other references by the change that needs them
- A rendered change that is about to be handed over reaches the capture reference
- A planning, building, or reviewing role reaches the skill by name, with or without the governance pointer installed

## Must not

- Reword a moved rule in the move, since a wording change is a separate change with its own ledger row
- Restate the look, being layout, type, color, or the layer order
- Be reached only by an author typing its name, since the `ui-craft` pointer rule and the planning, building, and reviewing skills are its callers

## Out of scope

- How a surface looks, which `design-taste` owns
- The design folder, its references, and the comparison a pull request shows, which `design-record` and the `design-reference` rule own
- The visual checklist a reviewer reads, which `ui-checklist` owns
