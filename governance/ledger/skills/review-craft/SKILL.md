# Review craft skill ledger

The field is code review. Google's reviewer guide carries the axes, Parnas, Ousterhout, and Beck as Fowler records him carry the design walk, and the skills pinned at `addyosmani/agent-skills@2686b620` carry the bar, performance, and scope checks.

The proof ladder and the evidence bar are this toolkit's own, so their rows name the failure each prevents. Closing sections and `## What this delegates` restate these rules or route, so they take no table.

Parnas's paper refused a read at its ACM DOI, `10.1145/361598.361623`, so the rows quote an open copy of the same paper.

## Open with the one fact the change's safety rests on

| Bullet         | Source                                                                                                                        | Read       |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Asserted       | House choice: a risky claim taken on the description's word merges unproven, since nothing marks it as the weakest proof      | 2026-10-24 |
| Pointed at     | House choice: a claim naming its test reads as proven when nobody opened the test, so naming the code is its own lower rung   | 2026-10-24 |
| Walked through | House choice: reasoning that traces the path still misses the input it never imagined, so it ranks below a test that runs     | 2026-10-24 |
| Tested         | House choice: a claim with no failing test regresses silently on the next change, so a test in the diff outranks any argument | 2026-10-24 |
| Reproduced     | House choice: a test can pass on a stubbed path, so a recorded run of the real thing is the one rung above it                 | 2026-10-24 |

## Hold every finding to the evidence bar

| Bullet                            | Source                                                                                                                                                                                                                              | Read       |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Confirm against the reviewed head | [Google, What to look for in a code review](https://google.github.io/eng-practices/review/reviewer/looking-for.html): "Usually the code review tool will only show you a few lines of code around the parts that are being changed" | 2026-10-24 |
| Quote the rule cited              | House choice: a finding citing a rule by name alone sends the author to find it first, and a paraphrase drifts from what the rule says                                                                                              | 2026-10-24 |
| Name the input that breaks        | House choice: a finding with no failing input cannot be reproduced or refuted, so the author either guesses at a fix or dismisses a real bug                                                                                        | 2026-10-24 |
| Drop what a gate already owns     | House choice: a review restating a linter or a type error reports it with less certainty than the gate, and the noise buries the findings only a reader can make                                                                    | 2026-10-24 |
| Drop what rests on unread state   | House choice: a finding about state the reviewer never opened is a guess posted as a fact, and the author spends a round disproving it                                                                                              | 2026-10-24 |
