# UX controls reference ledger

The field is interaction design, and the authorities are the Nielsen Norman Group, WCAG 2.2, Primer, Cloudscape, MDN, and web.dev. These bullets were split from `ux-completeness.md`.

## Destructive actions

| Bullet                                          | Source                                                                                                                                                                                                                                                                                                                                             | Read       |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Confirm unless undoable                         | [Confirmation dialogs](https://www.nngroup.com/articles/confirmation-dialog/): "consider a confirmation dialog before actions that cannot be undone", and "do try your best to offer undo"                                                                                                                                                         | 2026-10-18 |
| Cancelled edit restores, never discards unasked | [Primer, Edit pattern](https://primer.style/product/scenario-patterns/edit): "Put the content back to the value it had before the edit when someone cancels", and "Confirm before discarding an edit someone has put work into". The anti-pattern is to "Discard a half-written edit because someone pressed Escape or clicked outside the editor" | 2026-10-23 |

## Modals

| Bullet                              | Source                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Read       |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Modal only for a clear need         | [Modality](https://developer.apple.com/design/human-interface-guidelines/modality): "Present content modally only when there’s a clear benefit", since a modal "takes people out of their current context and requires an action to dismiss". The wording of the benefit as the person's full attention or an answer before continuing is a house reading                                                                                                                                                                                                                                                      | 2026-11-23 |
| Never a modal over a modal          | [Modality](https://developer.apple.com/design/human-interface-guidelines/modality): "Let people dismiss a modal view before presenting another one", and [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets): "Display only one sheet at a time from the main interface", closing the first before displaying the new one. The page excepts an alert: an alert "can appear on top of all other content", "including other modal views", and "you never want to display more than one alert at the same time", so the bullet lets a confirm or alert sit over a modal, one at a time | 2026-11-23 |
| Beside the control that revealed it | [Popovers](https://developer.apple.com/design/human-interface-guidelines/popovers): "Make sure a popover’s arrow points as directly as possible to the element that revealed it", and "Ideally, a popover doesn’t cover the element that revealed it". The page reserves popovers for wide views and gives a compact view "a full-screen modal view like a sheet instead", so a phone keeps the sheet. A confirm or alert belongs to no one control, so it keeps the centered placement as a house reading                                                                                                     | 2026-11-28 |

## Navigation

| Bullet                          | Source                                                                                                                                                                                                                                                                                    | Read       |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| A tab bar navigates, never acts | [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): "Use a tab bar to support navigation, not to provide actions". The page speaks of sections of an app, so the bullet leaves tabs that switch a view inside one section alone, which is a house scoping | 2026-11-23 |
| Every tab labeled               | [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): "Include tab labels to help with navigation", a label appearing "beneath or beside a tab bar icon"                                                                                                    | 2026-11-23 |
| Every tab stays shown           | [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): "Don’t disable or hide tab bar buttons, even when their content is unavailable", and "If a section is empty, explain why its content is unavailable"                                                  | 2026-11-23 |

## Permissions

| Bullet                          | Source                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Read       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Ask at first use of the feature | [Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding): "present a permission request when people first access the specific function that relies on private data or resources", with the request made in onboarding only if the app "needs access to private data or resources before it can function", which is about the whole app, so the bullet allows asking at load only when the page cannot work at all without the grant. The browser permissions named are the house mapping | 2026-11-23 |

## Element states

| Bullet                        | Source                                                                                                                                                                                                                                                                                             | Read       |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| Distinct interaction states   | [Visibility of system status](https://www.nngroup.com/articles/visibility-system-status/): "Did the system actually catch that button press", and an element with no pressed or hover response leaves the person unable to tell                                                                    | 2026-10-18 |
| Say why a control is disabled | [Cloudscape, Disabled and read-only states](https://cloudscape.design/patterns/general/disabled-and-read-only-states/): "Use disabled reasons where adequate context is not provided through disabled button or label text", and `aria-disabled="true"` is used "so that it will remain focusable" | 2026-10-23 |
| Declare `color-scheme`        | [MDN, color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme): the user agent adapts "The default colors of scrollbars and other interaction UI" and "The default colors of form controls", and the page opts in by declaring it on the `:root` element  | 2026-10-23 |
| No intermediate flash         | [Cumulative Layout Shift](https://web.dev/articles/cls): "Unexpected layout shifts can disrupt the user experience", caused by content "dynamically added to the page before existing content"                                                                                                     | 2026-10-18 |

## Signifiers

| Bullet                              | Source                                                                                                                                                                                                                                                                                                                                 | Read       |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| No control look without an action   | [Beyond Blue Links](https://www.nngroup.com/articles/clickable-elements/): "Conversely, don't make nonclickable items look like buttons." [Flat UI Elements Attract Less Attention](https://www.nngroup.com/articles/flat-ui-less-attention-cause-uncertainty/): "UIs with weak signifiers required more user effort than strong ones" | 2026-11-08 |
| Default cursor on decorative chrome | [MDN, cursor](https://developer.mozilla.org/en-US/docs/Web/CSS/cursor): `pointer` is "a pointer that indicates a link", and `default` is "The platform-dependent default cursor"                                                                                                                                                       | 2026-11-08 |

## Hover and focus effects

| Bullet                                 | Source                                                                                                                                                                                                                                                                                                                                                                                      | Read                 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| Hover and focus content                | [Understanding Content on Hover or Focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html): additional content is "Dismissible" without moving hover or focus, "Hoverable" so the pointer can move over it, and "Persistent" until "the hover or focus trigger is removed, the user dismisses it, or its information is no longer valid"                         | 2026-10-23, WCAG 2.2 |
| No change of context on focus or input | [Understanding On Focus](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html): "When any user interface component receives focus, it does not initiate a change of context". [Understanding On Input](https://www.w3.org/WAI/WCAG22/Understanding/on-input.html): changing a setting does not cause one "unless the user has been advised of the behavior before using the component" | 2026-10-23, WCAG 2.2 |
| Hover behind a hover query             | [MDN, hover](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/hover): `none` covers devices where "many mobile devices emulate hovering when the user performs an inconvenient long tap", and `hover` means "The primary input mechanism can conveniently hover over elements."                                                                                                      | 2026-11-08           |
