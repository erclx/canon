# Architecture

Authoring guidance: `standards/architecture.md`.

## Overview

The toolkit is a CLI plus a Claude Code plugin, built so an agent can drive every surface a human can. Content is authored once at a project-root folder, consumed here through a generated copy under `.claude/`, and reaches a target project either by a `canon` install command or by loading live from the plugin root.

Six domains carry the weight: governance rules, standards, snippets, tooling stacks, plugin skills, and the CLI that installs them. This file holds each cross-domain decision and the alternative it passed over. The mechanism behind one lives in `canon/context/<domain>.md`, which is where a reader goes for how rather than why.

## Key technical decisions

### Two delivery paths rather than one

`canon` commands copy governance rules, standards, snippets, and tooling configs into a project, and the marketplace plugin loads skills live from `claude/`. A single channel was the obvious alternative, and neither channel does the other's job. Copied content is what a project edits and owns, so it lands as real files under version control, while a skill is toolkit-owned process that goes stale the moment it is copied.

What the split costs is a citation crossing it, since a skill body naming an installed path resolves only for a project that ran the matching install and an unresolved path raises nothing until a session opens it. A file only one skill reads therefore travels inside that skill, which is what moved the three orchestrator runbooks into `claude/skills/role-orchestrator/references/`. Publishing on both surfaces was the alternative and it makes two sources for one text.

### A standard travels two routes, neither of which writes into a project

`standards/` reaches a project two ways, and no install channel exists: the `claude/standards` symlink puts the whole corpus in every plugin cache, delivering self-containment to a session, and the published package carries the corpus as the CLI's root, delivering it to a machine reader. `canon standards install` used to write the flat root into a target, and that route closed because every copy became a file sync had to reconcile forever, measured at five relocated standards sitting 12 to 45 lines behind with no command able to refresh them. A project holding an old `.claude/standards/` copy resolves nothing through it, since the resolver reads `standards/` at the working root and then the package alone. Measured at `3ac31a09` on 2026-08-20.

`tooling/<stack>/reference.md` closes the same channel for tooling stack references: `src/tooling/read.ts` resolves a reference at the working root ahead of the packaged corpus, mirroring `standardRoots` in `src/standards/read.ts`, and `canon tooling reference <stack>` is the read verb `canon tooling sync` stopped writing a copy through. Measured at `16591fd2` on 2026-08-27.

`standards/bundled/` is retired. It held six sources copying out eleven times, and growing it to cover the flat corpus was declined on a duplication measurement: the most-cited standard, named by 21 skill bodies across the two catalogs, would have landed a copy in each. The fallback citation form thirty-nine bodies already carry, `${CLAUDE_SKILL_DIR}/../../standards/<name>.md`, serves a root standard to any number of readers at zero copies, so the six sources moved to the flat root and the eleven copies came out with them. Measured at `16a80339` on 2026-08-25.

A census over all 27 standards, uniform at the flat root now that the fan-out is gone, bounds the corpus. Measured at `bd2be81a` on 2026-08-20. `canon/context/standards/destinations.md` carries the per-standard record, the empty drop bucket, and the three destinations withdrawn without being built, one of them a move to the retired fan-out. Those three stay in the flat corpus reached by citation. Measured at `653bbb15` on 2026-08-20.

A machine-parsed standard is permanently exempt from any design inlining a standard into the rule that cites it, because a rule restating the list a parser reads is two sources for one list. The set is empty: the three ban sets and the six structural checkpoints that made `markdown.md` a member ship as data in `src/markdown/` instead. Relocating a list to a single source the machine owns satisfies that bar rather than breaking it, at the accepted cost that the prose and the shipped numbers can now drift with nothing comparing them. Measured at `60fc97bf` on 2026-08-19.

### The toolkit consumes its own output

`governance/rules/` authors at the repository root and this repository commits its own consumed copy at `.claude/rules/`, regenerated by `bun run check` and asserted for drift. A citation then spells one path that resolves here and in every target that installed the same content, where reading the authoring root directly would have left each one needing two spellings.

`standards/`, `snippets/`, and `internal/` carry no mirror, since nothing installs any of the three corpora into a project. `standards/` bought only a path this repository resolved, at a cost of 28 tracked files regenerated on every check and a citation form that read as portable and was not, which is why 40 of the 62 shipped bodies name the plugin root instead. `internal/rules/claude/598-authoring-layout.md` states the root each of the three carriers resolves against. The accepted cost is that a citation here reads differently from the same citation in a rule or a shipped body, so a reader has to know which surface they are on. Measured at `7374bb51` on 2026-08-28.

`snippets/` needed no mirror because the live `claude/snippets` symlink already served every plugin cache, and `internal/` never had an install channel to close, since its one standard has two readers who both sit at the root beside the source. What came out was 15 tracked files and `mirror_dir` itself, leaving `scripts/core/regen-claude-copies.sh` with no mirror call and one delegation to `canon gov regen`. Measured at `23e79fbd` on 2026-08-28.

A comparably-shaped external project reached the same mechanism for its own install-and-update path without sharing any code with this one: hash what shipped, compare it three ways against what the project holds and what it last recorded, and skip whatever the project edited. Its version is 779 lines against `src/sync/`'s 5,787, and the convergence matters more than the gap, since two projects reasoning independently landing on one answer is stronger evidence for the mechanism than either project's own reasoning taken alone. Measured at `d5f519ee` on 2026-08-26.

### Location enforces the plugin boundary

Toolkit-internal content lives under `internal/`, a tree nothing inside `claude/` reaches. `scripts/core/check-plugin-boundary.sh` walks the shipped tree with symlinks followed and fails on any file resolving under `internal/`. A filter at each CLI entry point was the alternative and it failed in production, since `claude/standards` and `claude/snippets` are symlinks an installer dereferences with nothing left in the path to filter, which let five internal files reach every plugin cache.

`SyncAdapter.projectSubdir` answers the same question in the sync engine by deciding by location before any name lookup runs. `locateSource` used to judge an installed file by name alone, and relocating five toolkit standards into a subfolder made a sync read them as project-authored with no command able to tell the two apart, which a repair pass across three targets found in 17 such files. The name inference stays live at the flat root as a floor under new files rather than being replaced. Measured at `5da3214d` on 2026-08-25.

### Three tiers of context rather than one file

Context splits three ways: `CLAUDE.md` and this file load eagerly, `.claude/rules/` load on glob match, and `canon/context/<domain>.md` is read on demand. One large `CLAUDE.md` was the starting point and grows without bound. Nested `CLAUDE.md` files below the cwd were the other candidate, and they load cheaply but announce nothing, so a session never learns they exist. The `index.md` catalog is what the third tier buys, since it lists every entry up front and a session picks what it needs before touching the domain.

### Three axes decide which tier a fact belongs in

A fact goes to `.claude/rules/` when it fires on a specific path being edited and violating it ships silently, and to a context entry or a skill body otherwise. Recording it in the entry's `## Gotchas` instead reaches too little, since eager loading does not substitute: a rule delivered at session start competes with the whole file, while a glob-matched one arrives attached to the action. The test rejects most of what it is run over, because a rule per gotcha rebuilds the `CLAUDE.md` the tiers exist to prevent.

Firing is one axis of three. The second is conditional presence, which is what a rule buys that a line in `CLAUDE.md` or a seed cannot: a rule loads only for the session whose path matches, where an eager line loads into every session regardless of what is being edited.

The third is updatability, which is what makes `governance/rules/core/` correct as rules for the fifteen of its nineteen rules carrying no `paths:` glob, which load every session anyway since every stack reaches `base` and `base.toml` takes the folder whole. A rule installed through governance sync still carries a later fix to every project that installed it, where a seed line stays fixed at the scaffold it was written into. Measured at `5196cc9a` on 2026-08-27.

The test itself is a fact about editing the root file, so it ships as `governance/rules/claude/592-claude-md.md` and arrives attached to that edit in every target that installed governance. A project scaffolding without governance is reached by neither surface, since the seed carries four sections and none of them states the test. A target that did install governance gets it from two surfaces, this entry and the shipped rule, and nothing compares them.

### Something other than the model resolving a file by path decides whether it installs

A domain installs as a file when something other than the model resolves it by path, and ships as a command when only a session's own judgment would open it. The harness glob-loads a governance rule and expands a snippet the moment an `@` reference fires, and a target's own build tooling reads a tooling config straight off its path, so none of the three needs a command in the loop. A standard is the one domain the model opens on purpose, since nothing else resolves it by name, which is why `canon standards` carries no install and no sync and its own help says so. Deciding per domain case by case lost to writing the criterion down, since four domains had already landed on this one consistent answer with nothing stating it until this row read it back.

Design answers the same criterion the same way: a target's own stylesheet resolves `.claude/design/base.css` off its path with no session in the loop, so it installs as a file too. Naming the criterion here builds no check that a domain answers it the same way, so a mismatch is caught only by a person reading the criterion. A second cost sits beside it: every session pays to read this entry, since `.claude/ARCHITECTURE.md` loads eagerly rather than on demand. Measured at `af5a4b87` on 2026-09-01.

### Skills call the CLI and never reimplement it

A plugin skill reads a catalog through `canon <domain> list --json`, matches it against project context, then executes the CLI under `CANON_NON_INTERACTIVE=1`. Every domain owes a `list` verb with `--json` and no skill hardcodes a rule, stack, or snippet name, which keeps one behavior in one place rather than restated in a skill body that could drift from the CLI on its own cadence.

The rule covers a catalog and stops at a document, so a skill reads a standard by path off the `claude/standards` symlink that puts the corpus in every plugin cache, and 38 shipped bodies name that fallback. A rule cannot take that path, being markdown a glob match loads with no skill context, so `${CLAUDE_SKILL_DIR}` expands to nothing and the 18 rules citing a standard name `canon standards <name>` instead. Describing the plugin corpus in prose was tried first and converts a working citation into a reported failure while reading ambiguously against a project-root `standards/` folder. Measured at `e5abee70` on 2026-08-20.

### TypeScript with a bash exec boundary

`src/` parses arguments and owns every migrated domain, and `scripts/` holds what has not moved, with domains migrating one verb at a time rather than in a single rewrite. Bash keeps only what it is good at. `read_frontmatter_field` stayed because three scripts, two of them list scripts, call it once per field inside a loop, where routing through the CLI would cost a process per read. Coarse operations called once per invocation shell into `canon` instead.

### Bun as the runtime with no build step

`bin` points at `src/cli.ts` and its `#!/usr/bin/env bun` shebang runs the source directly, so the package ships TypeScript with `tsconfig.json` beside it and nothing compiles. Node with a build step was the alternative, and it costs a publish pipeline plus a `dist/` that can drift from the source a contributor reads. The trade is that the CLI does not run under Node at all, since `Bun.Glob`, `Bun.TOML`, and `Bun.YAML` stand in for globbing and parser dependencies, so a target project needs Bun on the machine rather than only a package manager.

### Hooks enforce what prose only states

A rule written in a standard fires only when a session reads it. The Claude Code hooks in `.claude/hooks/`, the husky hooks, and the drift stages in `bun run check` fire either way, and the scratch-guard hook, the task-board index regen, and the consumed-copy drift assertion each replace an instruction that prose alone left ignored. The cost is that an enforcement point is code with its own failure modes, so each one has to say what it does when its inputs are missing rather than reporting a pass.

Where a check sits decides whether it fires at all. `.github/ISSUE_TEMPLATE/toolkit-feedback.yml` marks fields required and enforces that inside the web composer alone, while every feedback issue on this repository is filed by `canon feedback --github` through `gh issue create --body`, which never renders a form. `REQUIRED_FIELDS` in `src/commands/feedback-format.ts` carries the list instead, refusing on both write paths rather than on the one that never runs. Widening the form's own required list was the alternative and it lost, since it changes nothing about a report the form never sees. What it costs is a second copy of the list, since the form stays as the web mirror with nothing comparing the two, and `blank_issues_enabled: false` closes the route around both at the price of every non-feedback issue losing its web form as well. Measured at `d60b3117` on 2026-09-01.

### Content that leaves the repository gates harder than content that stays

The same finding fails a push against `tooling/*/seeds/` and only reports against `canon/context/`. What moves it is the corpus rather than the measure: a seed is authored once and installed into every scaffolded project, so a defect there propagates, while a context entry is edited by the people who own it and a threshold failing their push teaches them to route around the stage. Widening the `paths` globs on the claude rules was the alternative and it is a nudge, since a rule loads only when a session opens the file. Gating a measure with a known false-positive class forces an escape hatch, so `stub: true` exempts a seed and both install paths strip it before a target sees it.

### A diagram folder per kind rather than one file

`.canon/diagrams/` holds an entry per kind under a fixed filename, chosen over a single `DIAGRAMS.md`. The kinds drift at rates spanning roughly an order of magnitude, so a deploy change rewrites one entry and leaves the others untouched. Fixed filenames are what let a session refreshing a kind find the file it is meant to overwrite instead of writing a second entry beside it under a name of its own. A kind carrying a second question takes a suffixed name and repeats its category, which is how the folder reaches nine entries across five kinds.

### Review travels on the pull request

`review-pr` posts findings as a comment on the pull request rather than returning them to the session that produced them. A finding posted there survives either session ending, which is what an orchestrator and worker pair need when neither outlives the review. `review-branch` still runs locally against the branch diff before a push, so the two compose rather than compete: the local pass catches what it can before the branch leaves the machine, and the pull request holds the durable record.

### Evals measure spec quality rather than efficacy

`scripts/eval/` asks whether a session that has never seen a standard can author a conforming artifact from that standard alone, and says nothing about whether the artifact is useful. No baseline arm and a sample of one are correct for that question, because failure is self-evident: a session that reads the standard and still writes the wrong shape has proved the standard failed to communicate its own central rule. The fixture extracts to `mktemp -d` outside this repository, since a fixture under the root inherits this project's `CLAUDE.md` through the ancestor chain and the session under test would arrive already knowing what the test measures.

### A durable record is named for what it is, not for how long it lives

`groundwork/`, the three archives, and `.canon/review/evidence/` sit outside `.tmp/`, leaving it to hold only what can be deleted without loss. A folder cited by task files months after it was written fails that test, so a folder announcing itself as temporary is the wrong container for anything a later session is meant to find.

`memory-archive/` stays under `.tmp/` on the same test, since nothing cites a retired memory and it is an undo buffer rather than a record a later session opens. One entry is the exception: `feedback-a-git-skill-governs-how-not-whether.md`, cited by an archived plan and an archived task row, both citing surfaces closed rather than live, so it is found through history rather than through the pen. `governance/rules/core/045-memory.md` already routes a retirement there regardless.

Nine further folders sit at `.canon/review/evidence/` rather than under `.tmp/`, since a durable record, live or archived, names each as its evidence, and no source file writes into it on a schedule of its own. `canon migrate scratch-evidence` applies both clauses mechanically. Measured at `3208052c` on 2026-09-06, at nine folders, thirteen files, and twenty-nine citations across twenty-two files.

The memory-review archive sits at `.canon/review/memory/archive/` rather than `.tmp/`, because a receipt is not uniformly decided. It held 154 receipts and 261 undecided items, which the memory standard calls decision state the next round reads back, so it fails the deletable test on content rather than on citation. Measured at `961aa69c` on 2026-08-20.

Prefixing the remaining five record surfaces with a dot to collapse the ignore file into one pattern was declined at 486 occurrences across roughly 150 committed files against 80 for the move that shipped. It would be a breaking rename for every installed target and would hide the board a person opens daily. `.tmp` is the only one of the six where hidden is the correct default.

A record folder owns its lifecycle subfolders, so an archive is a location inside the record rather than a sibling named after it, and a folder earns root position only when nothing else contains it. Two surfaces both named for memory archive to two different places under that rule, a retired entry to `.tmp/memory-archive/` and a review receipt to `.canon/review/memory/archive/`, which the deletable test separates correctly. Measured at `106115ba` on 2026-08-21, at 94 occurrences across 37 tracked files, with a further 139 in the gitignored record tree that no `git grep` reaches.

### The population of consuming projects is recorded as it is created rather than searched for

`putDomain` in `src/sync/stamp.ts` writes each stamped target into a machine-level index beside the sandbox tree, so a project joins the population at the moment a sync installs into it. Sweeping the filesystem is the fallback rather than the primary answer, since a walk answers about the paths someone thought to name while a record answers about the installs that happened. A hand census run twice against one folder on one machine got both wrong: it reported six consuming projects across eight folders, where two had never been targets, one was a second clone of a target already counted, and the clone a repair actually ran in sat outside the folder entirely.

The sweep stays as a fallback because the index only knows an install that ran after it shipped, and it carries the bound with the answer, naming the roots walked, the depth, the folders it stopped at, and the roots it could not read. A stamped folder can contain other stamped folders, since one repository here holds the eight the census walked, and a linked worktree carries a copy of its own target's stamp, since one target here has five. Grouping by origin is what makes a target held in two clones count once. Nothing removes a row, so a project that was deleted or dropped the toolkit inflates the count until a read refuses its path. Measured at `427213fc` on 2026-08-30, against eight targets on this machine.

### The durable records back up through a second git directory, not a branch here

`canon records push` carries the gitignored record folders to a private repository through a second git directory at `.canon/.records.git` with `.canon/` as its work tree, so every path stays where it is. A separate checkout was the alternative, and it would move the 255 tracked files that spell one of these paths, which is the whole cost the second git directory exists to avoid.

Three counts describe this surface and each answers a different question. Nine is what a disk loss would take, which is `BACKED_FOLDERS`. Eleven is what sat under the old root as an ignored folder, counting the scratch folder that is deletable without loss and `worktrees/`, whose contents belong to the enclosing repository already. Twelve is what the move to `.canon/` relocated as ignore entries: the eleven less `worktrees/`, which stayed, plus the history directory and the `README.md` a records pull writes back.

An orphan branch on this repository was the cheaper alternative and it is the one this repository cannot take, since it is public and the payload is the memory pen, the review reports, and the groundwork trails. What the split costs is a one-time setup per machine, which both verbs refuse until it exists, and a remote gate that compares the records origin against every remote of this project. The work tree moved with the records rather than being pointed at them, so the history's own paths are unchanged: `recordRoot` resolves the root and `workTree` takes whatever it returns, which keeps a half-migrated tree from opening a history at one root and staging a work tree at the other. Measured at `ca020184` on 2026-09-01, at eleven folders.

### A write to shared scratch routes on what it does to the file

Shared session scratch lives at the main worktree root, and a linked worktree is where every worker runs. `Edit` and `Write` refuse a main-root path from there and offer the worktree copy instead, since a body naming only the destination can report success while losing the write. The same refusal reaches a background session that entered no worktree at all, since the guard gates on isolation rather than on sitting inside one. Creating a whole file goes out as a plain single `Bash` command carrying a heredoc, and changing a line inside a file that already exists goes through a `canon` verb that resolves the root in-process.

Instructing the shell for both was the alternative and it ships the stream editor this repository already bans. Relocating the four scratch folders was the other candidate and it addresses nothing, since the refusal is tool-scoped rather than filesystem-scoped, and it would be a breaking rename for every installed target. What the split costs is that two structured edits became code with tests rather than a sentence in a skill body, which is `canon tasks pull-request` and `canon tasks outcome`.

### A held skill body is checked against history rather than against itself

A session loads a skill body once and keeps it, so an edit made this session is not picked up, and a compaction carries the held copy forward with the summary. A held body naming a file the branch deleted fails loudly, while one naming a file that still exists and says something different resolves and reads current, so the session applies the superseded rule and reports success. That second shape is the ordinary ship shape here, since a branch touching `docs-fold`, `git-stage`, or `git-pr` runs those skills later in the chain that edited them.

`canon claude skills drift <ref>` names which shipped bodies moved between a ref and `HEAD`, and `standards/session.md` runs it while a session map is written. Comparing the bytes a session holds cannot be built, because a session has no way to read its own loaded body back, so the substitute reports a file moving rather than a held copy differing. `governance/rules/claude/570-skill.md` carries the instruction on the body being edited instead, since instructing a session to re-invoke the skill fixes nothing and a re-read step in the ship chain is declined on cost. Measured at `34ce48e6` on 2026-08-20.

### A standard governs an artifact's shape and the skill driving it governs the procedure

`standards/teach.md` fixes the layout, the ordinal naming, the frontmatter, and the mission and learning-record formats of a learning workspace, while the pedagogy that decides what to teach next sits in `teach-workspace/references/`. An attribute standard beside `markdown.md` was the alternative and it is declined on the second-reader test, since a standard nothing else cites has no owner to correct it. Folding the pedagogy into `standards/teach.md` was the other candidate, and `591-standard-authoring` rules it out, since a standard governs one document type or one attribute rather than both.

The glossary shape carries the same reasoning: it moved out of `teach.md` and into `standards/glossary.md`, a standard of its own beside the pedagogy it was separated from. `561-teach.md` reaches it through `canon standards glossary`, which is the form `598-authoring-layout` fixes for a rule read with no skill context. `standards/teach.md` carries only prose naming the skill's reference, not a path a check could resolve or find dead, since `canon gov citations` never opens `standards/` and the `context citations` gate stage matches a record-root shape rather than a skill's own reference. Measured at `285723bc` on 2026-09-06.

The workspace is the first record folder named `<nn>-<topic>` rather than by a bare slug, so a listing sorts by when each opened. That was free here because the surface was greenfield. The groundwork and intake folders share one ordinal sequence across both kinds instead, derived from the first commit naming a folder where one exists and from filesystem timestamps otherwise, and the CLI's slug resolution widened to match a bare topic against its ordinal-prefixed folder. Measured at `d5f519ee` on 2026-08-26.

### A producer hands off through a file of its own rather than a shared one

`teach-workspace` proposes where a durable page belongs and writes each confirmed one to `.canon/tmp/teach-promotion/<slug>.md`, which `docs-fold` folds and deletes. Sharing `.canon/tmp/memory-routing/<slug>.md` was the obvious reuse and it is what the pattern cannot take, since that file already has two writers and a reader that deletes it, so a fold triggered by one producer discards whatever the other wrote and never read. A sibling path costs the folding skill one more read and removes the interaction entirely.

The fold reaching the public docs corpus is the cost, since `docs-sync` owns that tree, and the carve-out is landing a page whose destination an operator already confirmed. Splitting the fold across two skills by destination was the alternative and it puts one handoff file under two readers, which is the failure this decision declines in the other direction. Measured at `f0f8bd62` on 2026-08-19.

### A rule the model can talk itself out of moves into a verb

Quiz option order is drawn by `canon teach lesson` rather than stated in the skill body, since an author told to vary a position still varies it by judgment, and a verb is a check where an instruction is a hope. What the split cannot close is that the body remains free to reorder what the verb reports, since nothing downstream compares the two, so the sandbox arm records that as a manual entry rather than claiming it.

`canon tasks plan-branch` (`src/tasks/branch.ts`) replaces the same shape for branch naming: a worker deriving a branch name and type from its own reading of a plan produced three strings for one plan across four dispatches, and the verb makes the dispatcher's check and the worker's branch one derivation instead of two readings. See `canon/context/claude-internal/orchestration.md` for the mechanism. The fallback it leaves open is a target whose installed binary carries no `plan-branch` subcommand, reading the plan by hand instead. Measured at `285723bc` on 2026-09-06.

### A writing rule travels by whether anything reads it

`standards/prose.md` is retired and its two halves went to different carriers. The bans, the spellings, and the frontmatter wording joined `markdown.md`, which every markdown edit already routes to and which `canon markdown audit` measures from package data. Voice, rhythm, sentence construction, and information density went to the `write-human` skill, and `500-prose` routes a markdown edit there. One file held both halves and made an enforced rule and an advisory one look identical, so a session was graded on the words it avoided and never on how the prose read.

Folding the bans into the skill instead was declined, since it would put the enforced list behind a glob-matched pointer beside the judgment it was separated from, and keeping a thinner `prose.md` would leave an advisory file under a name that already reached nobody. The split cost a 90-file citation sweep and a standard citing a skill, and nothing measures whether output follows the rhythm rules. Measured at `57ee7467` on 2026-08-20.

### A safe behavior sits on the default path rather than behind a flag

`canon tooling sync` writes nothing until `--write` is passed, and a headless run without it reports and exits 1. `CANON_NON_INTERACTIVE=1` used to default the confirm prompt to apply-all, so every scripted sync overwrote the target unasked, and against a real target one run deleted a deploy job, replaced a 120-line screenshot harness with the two-case starter, and reverted a shipped fix, across a golden-config category holding 41 files across 6 stacks. Naming a stack is not consent to lose an edit inside it.

An opt-in `--dry-run` was the alternative and it is declined, because a flag you have to remember is one nobody passes the first time, and the first time is when the target still holds the work. That inverts the contract for every caller, which is the accepted cost, and anything relying on `CANON_NON_INTERACTIVE=1` to mean yes is broken by the change. The interactive prompt is untouched, since inverting a default that already behaves correctly would churn the one path that never caused the damage. Measured at `0c953078` on 2026-08-20.

### The memory pen is bounded by an ownership test rather than by a type

`.canon/memory/` keeps whatever no context entry owns, and the four types are equal members of that residue. Reading all 145 `project`-typed entries against the domain catalog put 98 with a domain entry, 44 with no owner at all, and 3 already promoted elsewhere. Moving the pen to match `project` as its own governing type was the alternative and it lost on that middle number, since the 44 state an approach governing how the agent works and no context entry owns any of them, so the ownership test decides the boundary rather than the type a memory carries, and `standards/memory.md` admits `project` as a first-class type. Measured at `c7e92612` on 2026-08-20, at 98 entries retired into an archive now holding 100.

### Color is a question about a destination rather than about the process

`palette(stream)` in `src/ui.ts` reads `NO_COLOR` and the stream's `isTTY` at write time, and every writer asks about the stream it is about to write to. A single process-wide answer is wrong for this repository, since framed output goes to stderr and a structured record goes to stdout, so a run piping only its data keeps a terminal on stderr and keeps its color there. `showHelp` in `src/cli.ts` is the one framed surface on stdout and asks about that stream alone, while `process.stdin.isTTY` stays a third, separate question about whether a caller can be prompted.

Sixteen files route through the one module, since a fix scoped to it alone would leave most of the surface emitting while reading as done. `src/ui.test.ts` walks the tree and fails on an escape constant defined anywhere else.

## Risks / open questions

- Skills and the CLI ship at two speeds. A skill merged to `main` reaches a `--plugin-dir` session immediately, while the CLI reaches a user only once a release cuts a tag and the publish job lands it on the registry. A skill calling a verb or flag that has not been published yet fails in a target, and nothing detects that call.
  - `canon sync --check` and `canon claude skills drift` each read the installed version against the newest published one, but neither reports which verb is missing, so a session still meets the absent subcommand rather than a warning naming it, and a reader who never runs either check is reached by no route at all.
  - A missing subcommand under a command that exists is the quieter failure. `archiveTask` now owns the archive rule with no skill body restating it, narrowing the duplication between the two, but a target on an older binary still archives a task and leaves its plan live, reporting success either way.
  - Nesting each archive inside the record it archives (`.canon/plans/archive/`, and the older `../plans-archive/` and `../.tmp/plans-archive/` spellings) is documented as the convention a project receives in `standards/tasks.md` and `standards/plan.md`. A binary reading the nested convention but predating the change fails closed, refusing a task whose plan has already archived, which is the safe direction. An older binary still, predating archiving altogether, has a quiet counterpart: it does not refuse, it writes successfully to a flat `.claude/task-archive/` sibling instead, which is the failure that reached this repository itself on 2026-08-27, caught by a status read rather than by any check. The one known target still on the flat layout, `erclx.dev`, has no checkout reachable from this repository to run the move in.
  - `500-prose` and `561-teach` point at a skill carrier a project installing governance without the plugin does not have. Each rule tells a session to say so rather than proceed, which reports the gap without closing it, and nothing detects it at install time.
  - An exit code says nothing about a `canon` call here, because an operator's shell profile may wrap the binary in a function whose status comes from a trailing command, so every non-zero exit can read as 0. It masks an ordinary refusal exactly as it masks an absent verb, which is why every task verb tells a caller to branch on the record's `reason` rather than on the exit.
  - `git-pr` calls `canon labels audit` and keeps the stated matching rule as a fallback for a record that never arrives, since the labels a target already resolves by hand and the uncovered-surface report only the verb carries are not the same thing. The duplication runs until a release retires it rather than blocking on one.
- `canon-operator` tests for a field it reads and answers an absent key as unread rather than as empty, a pattern the remaining skills could take rather than a check the repository runs. A sandbox run against a stale binary once reported a clean target by answering from a filesystem walk of its own instead, so the skew can reach a reader as a confident wrong answer rather than a failure.
- A marketplace install is a cached copy, which is the same skew in the other direction. Someone who added the marketplace and never updated runs old skills against a current CLI. Neither direction is detected.
- The skill-body drift verb answers only when a session runs it, the instruction to run it sits in `standards/session.md`, and it goes quiet on a body the running session edited and has not committed. A project consuming the plugin from a cache has no history behind the skills tree and answers with a refusal.
- Verification anchors on this file have a writer and a sweeper, and the sweeper reaches only what a diff can point at. `docs-fold` anchors a decision it amends and reports one whose cited path the branch touched, leaving the rest unchecked until someone re-reads it by hand.
- Mechanism detail sits in the context entry that owns it and this file keeps the decision and the alternative it passed over, which leaves a pointer with no check behind it, since nothing compares a decision here against the entry it defers to.
- Two classes of claim stay unflagged: one counting over a tree the branch never opened, and one citing nothing narrower than a single path segment. The second is deliberate, since a prefix match on `src/` or `.claude/` fires on nearly every branch.
- A `scripts/eval/` run costs roughly a dollar per arm, and authorizing that spend is the operator's while performing the run is not, since `run.sh` spawns its own headless session against a fixture outside this checkout. What can still send one back to a person is a permission classifier refusing the nested spawn, which an agent hands back rather than routes around. The harness has confirmed twice and discriminated zero times, so treat a pass as weak evidence until one arm fails.
- Context entries are never created automatically. `docs-fold` refreshes an entry that already exists and adds none, so a new domain stays uncatalogued until someone writes the first entry by hand.
- A native Windows checkout without symlink support materializes `claude/standards` and `claude/snippets` as plain files holding a path. The plugin then ships no standards and no stage notices, since every catalog command reads the real directories at the repository root.
