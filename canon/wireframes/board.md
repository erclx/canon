# Design board

Generated by `canon design board` (`src/design/board.ts`) into a gitignored record folder, opened with `canon serve`. Reads from a caller-resolved `--root`, defaulting to the main worktree. The surfaces panel's landing-page half and the whole components panel render only when that root is this toolkit's own checkout, since both read this repository's own build output.

## Regions

- Nav: a pill fixed at the top center of the viewport, one link per panel in panel order, the theme toggle last
- Header: below the nav, the page heading over two meta lines naming how the board is made and which skills draft and audit
- Panels: six sections stacked down the page under the header, in the order Tokens, Surfaces, Wireframes, Past candidates, Components, References. Each carries a numbered eyebrow over its heading over one embedded frame the full width of the column
- Surfaces halves: the Surfaces frame stacks two halves, the landing page over the teach workspaces, each with its own heading

The sketch stays until a capture of the board exists.

## States

| State       | Reached when                                | Shows                                                         | Evidence     |
| ----------- | ------------------------------------------- | ------------------------------------------------------------- | ------------ |
| filled      | Every panel's source exists under the root  | All six panels with their embedded documents                  | not captured |
| panel-empty | One panel's source is missing               | That panel's frame carrying one line naming what is missing   | not captured |
| outside     | The root is not this toolkit's own checkout | The landing-page half and the Components panel as empty lines | not captured |
| light       | The visitor picks light with the toggle     | The shell on the light ground                                 | not captured |
| dark        | The default, before any pick                | The shell on the dark ground                                  | not captured |

- Eyebrow labels are templated: "Panel 0`<n>`" where `<n>` is the panel's position, 1 through 6
- Surfaces empty halves: "No web/dist/ build. Outside this toolkit's own checkout, the landing-page half reads instead: "The landing page panel only renders in this toolkit's own checkout."
- Wireframes empty state: "No wireframe files under `canon/wireframes/`."
- Candidates empty state: "`<n>` folders under `.canon/picks/` and none carries a draft-and-pick arm capture. The archival capture step has not run since it shipped."
- Components empty state: "No web/gallery-dist/ build. Run bun run web:gallery, then regenerate the board." Outside this toolkit's own checkout, the panel reads instead: "The components panel only renders in this toolkit's own checkout."
- References empty states: "No `.canon/picks/references/` folder yet." and "`.canon/picks/references/` exists but carries no image yet."
- Components panel content is generated by `web/gallery-src/pages/index.astro`, cited rather than duplicated here: it renders every component under `web/src/components/` in a labeled section, naming `panel-group` and `panel-row` as unrendered since both take required props with no defaults.
- Tokens panel content is cited rather than duplicated: it is `canon design render`'s own output from `canon/DESIGN.md`. With no such file, the panel reads: "No canon/DESIGN.md at the repository root."

## Behavior

- The pill nav is fixed to the top of the viewport rather than scrolling with the page, so it stays reachable from any panel.
- The nav highlights the link for whichever section fills the most of the viewport as the visitor scrolls, the same largest-intersection-ratio rule `landing-page.md`'s own pill uses.
- The theme toggle swaps a sun icon for a moon icon depending on the active theme, matches `TEACH_CHROME`'s icon-swap convention, and persists the choice in `localStorage` under `board-theme` so a reload keeps the visitor's last pick.
- Each panel embeds its own document by `<iframe>` rather than inlining markup, so a stale iframe never blocks the shell around it from rendering.

## Not on this surface

- No editing. The board reads its sources and writes nothing back to them
- No install or sync. The board is generated per machine into a gitignored folder and never reaches a target
- No slides panel, since a rendered deck is a PowerPoint file rather than a page a frame can embed
