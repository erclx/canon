# Overview

## Overview

Several standards in the corpus carry a decision their own text does not explain. The standard states the rule, and the entry here states the measurement or the rejected alternative behind it, so a reader proposing a change can argue against the reason rather than the wording.

- The plan and memory standards were drafted against a live folder holding two or three files, so each was measured against its archive or its pen before its shape rules held
- The plan standard also carries two rules under separate headings that read as pointing opposite ways, and a constraint block measured against a tree that has moved by the time a worker reads it
- The tasks standard carries a readiness test that has to admit a row no fact on disk can confirm
- The publish standard splits one rule by destination, so the same reference takes opposite spellings on either side of the remote
- The architecture, teach, glossary, Mermaid, wireframe, and wiki standards each carry one decision about where a rule lives or how far it reaches

## Layout

- `standards/` owns the corpus these decisions constrain
- `src/tasks/` owns the plan answer reader and the board validator that read the plan and tasks standards back
- `src/labels/` owns `canon labels scan`, the verb behind the publish standard's destination-scoped checks

Each file covers one family:

- `canon/context/standards/per-standard/plan.md`: the plan standard, its answer contract, execution-time deviations, constraint expiry, and the branch description cap plans feed
- `canon/context/standards/per-standard/memory-and-tasks.md`: the memory standard, what the pen measured, and the tasks readiness test
- `canon/context/standards/per-standard/publish.md`: the cross-reference form, the destination test, and the two title checks
- `canon/context/standards/per-standard/surfaces.md`: the architecture anchor, teach and glossary, Mermaid, wireframes, and when a standard moves into its reader's skill
