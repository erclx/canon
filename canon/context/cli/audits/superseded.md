# Superseded-value sweep

- `canon gov superseded <old> <new>` is the one report here the aggregate cannot run. It takes the two values as required arguments, so there is no unattended invocation for `canon audits run` to schedule and no baseline count to retain.
- The key is the whole decision. A file-scoped map from a changed rule to what cites it reaches nothing, because a fixture asserting an old output names neither the rule nor the standard behind it, so the value both sides carry is the only shared key there is.
- It sits under `gov` beside `test-order` for the same reason that one does: both measure a stated convention against the tree, and a session already reaching for one finds the other. `standards` was the alternative and its argument slot prints a document, so a sibling subcommand there reads as a standard name.
- The corpus is the whole tracked tree plus untracked files git does not ignore, rather than the sandbox where every instance happened to sit. A fixture is the cheapest place for an assertion to go stale and not the only one, and a sweep scoped to `scripts/sandbox/` would be read as covering the class.
- Over-reporting is the design rather than a defect. A string appears for reasons unrelated to any convention, which is why the verb reports and why a same-line replacement annotates a finding instead of suppressing it. A fixture halfway through a repair carries both values and so does the line stating the change, and nothing here can tell them apart.
- That annotation strips the superseded occurrences before it tests the line. A convention dropping a segment leaves the new value a substring of the old one, so a plain containment test answers true for every finding and separates nothing. Measured on the slug transform, where `feature-` sits inside `feature-feat-` and the flag fired on all 20 findings before the strip and on 6 after.
- The strip covers one direction and the opposite one reports every repaired line bare. It separates a repaired citation from a stale one when the new value sits inside the old, and a rename extending a name rather than shortening it inverts that: stripping the old value out of a line that already carries the new one leaves nothing for the containment test to match, so the annotation never fires. Measured on `cli-script` to `bash-cli-script`, where every finding carried the replacement and none was annotated, against `toolkit-operator` to `canon-operator` on the same run, where the unrelated names annotated correctly. A reader meeting an all-bare report checks whether the new name contains the old one before treating any line as stale.
- An empty replacement answers false rather than running that test, and it is allowed rather than refused. Retiring a value outright is an ordinary reason to run this, and a containment test against the empty string is true everywhere, so the two together reported every finding as carrying a replacement that does not exist.
- `isBinary` sits at `src/binary.ts` rather than in the secret scan that shaped it. Both sweeps read the same corpus and neither owns a predicate about bytes, so leaving it put a `src/gov/` dependency on the secret scanner, which was the tree's only cross-domain import of it.
- The blind spot is stated on every run. One declaration went stale by citing the wrong standard for the transform and carries no value to key on, so the sweep closes most of this class and no part of that one.
- The third blind spot is a citation the pattern never matched, and it is the one a literal comparison creates rather than inherits. A family written as `canon-*` or `internal-<X>` carries neither value, so a rename across sixteen folders, run once per name, found two real leftovers, and reported clean over seven stale citations. Two of the seven had inverted, stating the old prefix as a guard, which is worse than drift sitting unread: a rule reading backwards fires on the next author.
- The stem is derived rather than named, because a list of names cannot reach that class by construction. It cuts at the segment the two values differ on and carries everything they share ahead of it, so `toolkit-operator` to `canon-operator` derives `toolkit` and `canon-cli` to `canon-shell` derives `canon-cli`. The shared prefix alone was the alternative and it reports the whole family on a rename of one folder, since `canon-cli` and `canon-feedback-file` share `canon`. An empty replacement derives nothing at all, since a retirement leaves no second value to diverge from and every stem would run to the first segment.
- Three forms report and the character after the stem and its separator decides all three, so one scan reads a glob, an angle-bracket placeholder, and the family written bare. What bounded the last one is the left edge: a separator directly before the stem puts it mid-name, which is what `canon-check-toolkit-` is, and four `mkdtemp` fixtures reported under it before that guard. A path separator or a backtick has to keep matching, which is why the separator decides one side only rather than joining the name class.
- A real rename over this tree names a small number of hits outside the change's own fixtures, which is the rate to hold to, since a version reporting a page of hits teaches the next rename to skip the verb.
- A hit in a markdown file carries the nearest heading above it. The line alone misreads: `Use the canon-* prefix on an internal skill` sits under `## Must not` and is a prohibition there, which a bare-line read would misread as an instance rather than a rule. Reading a rule body differently from prose was weighed and declined, since the inverted-guard case is two instances rather than a class with a measured rate, so the report carries the section and the reader judges.
- `canon-allow-superseded: <reason>` mutes a line, reading the same two-line placement rule as `canon-allow-secret` through `src/exempt-marker.ts`. The duplication that extraction removed was exact, and only the token differs.
- Measured against `d7ea41a4`, sweeping `feature-feat-` to `feature-` named `scripts/sandbox/claude/auto-ship.sh:66` and nothing else, matching the hand derivation exactly. The verb ships against a nearly clean corpus, so its value is the regression it stops rather than the backlog it surfaces.
